# Share TrackDraft with friends

The app builds with vinext/Vite and targets Cloudflare Workers. These commands
use the Worker configuration generated by the installed Cloudflare Vite plugin.
The existing Sites build metadata is preserved.

## Verify locally

Use Node.js 22.18+ (or a newer supported LTS) and the committed lockfile:

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run preview -- --port 4173
```

With the preview running, use another terminal:

```sh
BASE_URL=http://localhost:4173 npm run test:e2e
BASE_URL=http://localhost:4173 npm run test:e2e:gaps
```

The browser checks require Chrome and the installed Playwright CLI. On a fresh
Linux CI machine, install it with `npx playwright install --with-deps chrome`.
The gameplay check covers all four modes, results, refresh, and a second browser
opening a friend invite. It expects an unsigned-in browser and checks that guest
play does not send cloud session, challenge, or scorecard writes.

## Deploy to your Cloudflare account

```sh
npx wrangler login
npm run deploy
```

Wrangler prints the public Workers URL. Share that HTTPS URL with friends.
If your account has multiple Workers, use a unique name explicitly:

```sh
npm run deploy -- --name your-trackdraft-name
```

To inspect the deployment package without publishing:

```sh
npx wrangler deploy --config dist/server/wrangler.json --dry-run
```

After deployment, verify `/api/health`, start a guest draft, refresh after a pick,
complete the draft, and open a copied friend invite in a private browser window.
Local checks do not establish that the deployed environment works.

## Guest mode: no accounts or paid APIs needed

Friends can draft, get a local deterministic score, keep browser-local history,
and use seed invite links without Supabase, Spotify, YouTube OAuth, or Gemini
credentials. Progress and rankings belong to that browser; clearing site data
removes them. Friend play is asynchronous: share an invite and compare result
codes, rather than joining a live multiplayer room. Full invite links preserve
format, difficulty, era, and theme. A bare code uses standard Draft Battle rules.
Budget mode is local-only because the current cloud schema supports the three
original formats. External song playback depends on provider availability.

## Optional account and streaming integrations

For account-based cloud storage, configure Supabase and apply the existing repo
migrations using your normal database workflow. Supply the public URL and
publishable/anon key at build time; configure server environment variables on the
Worker separately. Set the production site URL and the actual HTTPS OAuth
callback URLs in the provider dashboards. Keep server credentials in Worker
secrets, never in `NEXT_PUBLIC_*` variables or source control. `.env.local` is for
local development; it is not a production secret deployment mechanism.

Cloud session APIs retain authentication and ownership checks. Guests continue
locally even when Supabase is configured. Sign-in, database writes, and provider
OAuth need their own production checks with a test account before advertising
those optional features to friends.
